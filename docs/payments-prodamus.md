# Приём платежей PinPosy через Prodamus — рабочая инструкция

Документ написан для человека, который **никогда не работал с Prodamus** и **не имеет статуса самозанятого**.
Здесь: как это устроено в коде, какие переменные окружения нужны на Render, как прогнать демо-платёж
и что делать с юридической стороной (включая приём платежей из других стран).

### Схема потока

1. Пользователь жмёт «Выбрать тариф «Старт»» → `POST /billing/create-payment`.
2. Бэкенд создаёт строку в `subscriptions` (`status = pending`, `provider_payment_id = pp-start-...`)
   и просит у Prodamus ссылку (`do=link`).
3. Браузер уходит на `https://<shop>.payform.ru/...`. Пользователь платит картой.
4. Prodamus шлёт `POST /billing/webhook` (`application/x-www-form-urlencoded`, подпись в заголовке `Sign`).
5. Бэкенд проверяет подпись → находит строку по `order_id` → `status = success`,
   `period_start`/`period_end` (+30 дней) → `users.tariff_plan = plan`, `users.tariff_period_end`.
6. Уходит письмо «Тариф активирован» (тот же SMTP, что у сброса пароля).
7. Пользователь возвращается на `/app?payment=success`, фронт опрашивает `/me` (0/3/8/15 с) — замочки снимаются.

## 3. Переменные окружения на Render (backend)

| Переменная | Обязательна | Значение / откуда взять |
|---|---|---|
| `SUPABASE_URL` | да (уже есть) | Project URL из Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | да (уже есть) | service_role key (не anon!) |
| `JWT_SECRET` | да (уже есть) | текущий секрет |
| `FRONTEND_URL` | да (уже есть) | `https://pinposy.com,https://www.pinposy.com` |
| `PUBLIC_BACKEND_URL` | **да, новая** | `https://pinboard-ai-backend.onrender.com` — из него собирается `urlNotification` (адрес вебхука) |
| `PRODAMUS_SHOP_ID` | **да, новая** | логин платёжной формы, напр. `pinposy` (даёт `https://pinposy.payform.ru/`) |
| `PRODAMUS_SECRET` | **да, новая** | «Секретный ключ» со страницы платёжной формы в кабинете Prodamus |
| `PRODAMUS_URL` | нет | явный адрес формы, если он не `<shop>.payform.ru` (напр. свой домен) |
| `PRODAMUS_SYS` | нет | идентификатор интеграции, выдаёт поддержка Prodamus (нужен для `urlNotification`) |
| `PRODAMUS_DEMO` | нет | `1` — все платежи идут в демо-режиме |
| `PRODAMUS_OFFLINE` | нет | `1` — не ходить в сеть (только локальные тесты) |
| `PRODAMUS_SIGN_PHP_ESCAPE` | нет | `0` отключает экранирование `/` в подписи (по умолчанию включено, как в PHP `json_encode`) |
| `MAIL_SMTP_HOST` / `MAIL_SMTP_PORT` / `MAIL_USER` / `MAIL_PASS` / `MAIL_FROM` | да для писем | уже используются сбросом пароля; без них письмо «Тариф активирован» просто не уйдёт (тариф всё равно активируется) |
| `ALLOW_TARIFF_SELF_SELECT` | нет | `1` — разрешить ручную смену тарифа (по умолчанию в production запрещено, кроме админа) |
| `NODE_ENV` | да | `production` на Render |

`GET /billing/health` покажет, всё ли подхватилось:
`{"configured":true,"demo":false,"webhook_url":"https://…/billing/webhook"}`.

## 4. Проверка в демо-режиме Prodamus (критерий задачи)

1. В кабинете Prodamus включите демо-режим / работайте на тестовой платёжной форме.
2. На Render: `PRODAMUS_DEMO=1`, `PRODAMUS_SHOP_ID`, `PRODAMUS_SECRET`, `PUBLIC_BACKEND_URL`.
3. Примените миграцию 006.
4. Зарегистрируйтесь на сайте, войдите, откройте «Тарифы» → «Выбрать тариф «Старт»».
5. В Supabase появится строка `pending`. Оплатите на странице Prodamus тестовой картой.
6. После оплаты:
   - в `subscriptions` строка станет `success` с `period_start` и `period_end`;
   - в `users` → `tariff_plan = start`, `tariff_period_end` ≈ +30 дней;
   - придёт письмо «тариф активирован»;
   - на `/app` замочки исчезли; в админке вкладка «5. Подписки и платежи» показывает платёж.

### Если вебхук не пришёл

- Проверьте `GET /billing/health` → `webhook_url`.
- В кабинете Prodamus укажите этот URL как адрес уведомлений. Если поддержка выдала `PRODAMUS_SYS`, его можно задать в Render, чтобы передавать URL уведомлений для конкретной ссылки.
- Логи Render: `[billing] вебхук отклонён: …` — значит не совпала подпись.
  Тогда переключите `PRODAMUS_SIGN_PHP_ESCAPE=0` и повторите платёж: разные версии API
  экранируют `/` по-разному. Код уже пробует оба варианта автоматически, но
  переменная помогает, если и это не сработало.
- Prodamus повторяет уведомление при не-200 ответе. Повторный `success` идемпотентен:
  второй раз тариф не продлевается (проверено тестом).

### Локальная проверка без Prodamus и без Supabase

```
cd backend && node ../test/billing-flow.js
```

Тест проверяет: создание `pending`, каноническую строку подписи, активацию на 30 дней,
идемпотентность, отказ при плохой подписи, отказ «Аналитике» в генерации, алиас `standard → pro`,
блокировку после истечения периода.

## 5. Правило тарифов

- `analytics` — только аналитика, генерация закрыта (и в UI, и на API).
- `start` / `pro` / `agency` — генерация открыта (`/boards/:id/pins/generate`,
  `/pins/:id/regenerate`, `/projects/:id/boards/generate`).
- `standard` — старое имя «Про»: алиас на `pro` (миграция 004 переименовала его).
- Тариф активен только пока `period_end` в будущем; после истечения API отдаёт
  `403 { code: "tariff_required" }`.

## 6. Юридическая часть: чего Prodamus требует и что делать без самозанятости

### 6.1. Что нужно Prodamus

Prodamus — российский платёжный сервис: подключение доступно **самозанятым (НПД), ИП и ООО,
зарегистрированным в РФ**. Самозанятым отдельно удобно: не нужна онлайн-касса, чеки уходят
в «Мой налог» автоматически. ([prodamus.ru/questions](https://prodamus.ru/questions),
[prodamus.ru/priem-platezhej-dlya-samozanyatyh](https://prodamus.ru/priem-platezhej-dlya-samozanyatyh))

Единоразовое подключение платёжного модуля — 10 000 ₽ для ИП / ИП на НПД / юрлиц, дальше только
комиссия с платежей ([prodamus.ru, страница для ИП](https://prodamus.ru/priem-platezhej-dlya-individualnogo-predprinimatelya)).

**Вывод:** «нет самозанятости» = нет кабинета Prodamus. Это блокер не в коде, а в статусе.
Три законных пути:

| Путь | Что делать | Плюсы | Минусы |
|---|---|---|---|
| A. Самозанятость (НПД) | Приложение «Мой налог», паспорт + ИНН, 10 минут | Бесплатно, без кассы, без отчётности | Лимит 2,4 млн ₽/год; нельзя нанимать сотрудников; только граждане РФ (иностранцам нужен статус резидента) |
| B. ИП | Регистрация ИП, УСН 6% | Нет лимита 2,4 млн, можно нанимать | Взносы, отчётность, касса при торговле |
| C. ООО | Юрлицо | Работа с B2B, крупные обороты | Дороже в обслуживании |

Лимит НПД 2,4 млн ₽/год — жёсткий: при тарифе «Про» 4 990 ₽ это ≈ 480 оплат в год.
Превысили — теряете НПД с начала превышения
([consultant.ru](https://www.consultant.ru/law/podborki/predelnyj_dohod_samozanyatogo/),
[banki.ru](https://www.banki.ru/news/daytheme/?id=11025827)).
Для SaaS с ростом это значит: **начинать можно с НПД, но планировать переход на ИП**.

### 6.2. Иностранные клиенты (у вас пользователи по всему миру)

Prodamus умеет принимать **зарубежные карты Visa / Mastercard / Maestro в EUR и USD**;
комиссия по таким платежам — **10%**, минимальный платёж 100 ₽, деньги приходят на рублёвый счёт
([prodamus.ru/priem-mezhdynarodnyh-platezhey](https://prodamus.ru/priem-mezhdynarodnyh-platezhey)).
В коде это уже учтено: `currency` в `create-payment` принимает `rub` и `usd`, каталог цен —
`POST /billing/plans`.

Честные ограничения, которые надо понимать заранее:

1. **Не все зарубежные карты проходят.** Это не глобальный эквайринг уровня Stripe: часть
   банков-эмитентов отклоняет платежи в адрес российского мерчанта. Реальный процент успеха
   зависит от страны плательщика и проверяется только практикой — обещать «весь мир» нельзя.
2. **Prodamus заточен под рублёвый расчёт.** Вы получаете рубли, а клиент платит валютой —
   курсовые риски и конвертация на стороне сервиса.
3. **Налоги в стране клиента.** НДС/sales tax для цифровых услуг (EU VAT, UK VAT, налоги штатов США)
   Prodamus за вас не считает и не платит. При продажах физлицам в ЕС это обязанность продавца
   (порог OSS — 10 000 € в год на весь ЕС).

### 6.3. Когда Prodamus не подходит и что вместо него

Если основная аудитория — **не Россия**, а вы хотите, чтобы налоги считал сервис, нужен
**Merchant of Record** (он продавец, он же платит налоги):

| Вариант | Для кого | Важное ограничение |
|---|---|---|
| **Paddle** | SaaS, цифровые продукты, глобальные карты | Работает только с продавцами из поддерживаемых стран; РФ в списке нет ([paddle.com](https://www.paddle.com/help/start/intro-to-paddle/which-countries-are-supported-by-paddle)) |
| **Lemon Squeezy** | инди-разработчики, быстрый старт | Не принимает платежи **от** клиентов из РФ, Беларуси и ряда стран; выплаты — на счёт в поддерживаемой стране ([docs.lemonsqueezy.com](https://docs.lemonsqueezy.com/help/getting-started/supported-countries)) |
| **Stripe** | максимум контроля | Для резидентов РФ недоступен напрямую |
| **ИП/юрлицо в Казахстане, Армении, Грузии + местный эквайринг** | те, кто хочет и РФ, и мир | Нужна реальная регистрация и налоговый резидентств/отчётность в этой стране; «фирма-прокладка» без присутствия — риск блокировки средств |
| **Крипто (USDT) / Payoneer / Wise invoices** | B2B, услуги, аудитория, у которой нет карты | Не карточный эквайринг, конверсия и доверие ниже; в РФ требует аккуратной налоговой трактовки |

Практичная рекомендация для PinPosy:

- **Сейчас (день 1):** самозанятость или ИП в РФ + Prodamus. Код уже готов, приём рублей и
  части зарубежных карт работает.
- **Когда появятся клиенты из ЕС/США:** держать Prodamus для РФ/СНГ и **добавить второй канал**
  (Merchant of Record или компания в стране с доступом к Stripe). Архитектура к этому готова:
  `subscriptions.provider_payment_id` + `status` не привязаны к Prodamus жёстко, `payment_provider`
  в `/me` — поле-заглушка под мультипровайдерность.
- **Не пытайтесь** «принять весь мир одной кнопкой»: ни Prodamus, ни один сервис этого не даёт
  из РФ. Ваш лендинг уже обещает «карты РФ и зарубежные» — формулировка корректна, но добавьте
  мелким шрифтом «доступность зависит от банка-эмитента».

### 6.4. Документы для клиента

Prodamus формирует чек (для НПД — через «Мой налог», для ИП/ООО — через кассу или без неё
в зависимости от режима). Оферту/условия подписки на сайте уже есть (`frontend/src/legal/terms.*`),
в них стоит отразить: срок 30 дней, автопродление отсутствует (продление — ручное, кнопкой
«Продлить тариф»), возврат — по закону о защите прав потребителей.

## 7. Чек-лист запуска

1. [ ] Применить `006_subscriptions.sql` в Supabase.
2. [ ] Зарегистрировать статус (НПД или ИП) и подать заявку в Prodamus.
3. [ ] Получить `PRODAMUS_SHOP_ID` и `PRODAMUS_SECRET`, прописать переменные на Render
       (+ `PUBLIC_BACKEND_URL`).
4. [ ] Задеплоить, открыть `/billing/health` — `configured: true`.
5. [ ] Прогнать демо-платёж, проверить `subscriptions` и `users.tariff_plan`.
6. [ ] Включить реальный режим: убрать `PRODAMUS_DEMO`.
7. [ ] Проверить письмо «Тариф активирован» (SMTP уже настроен под сброс пароля).
8. [ ] Проверить в админке вкладку «5. Подписки и платежи».
