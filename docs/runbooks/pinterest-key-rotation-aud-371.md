# PinPosy — Pinterest token encryption-key rotation (AUD-371)

> Операционная инструкция. Не вставляй значения ключей в GitHub, документы, чаты, тикеты или скриншоты. Не меняй production без отдельного согласования.

## Что нельзя делать

- Не удаляй `PINTEREST_TOKEN_ENCRYPTION_KEY_PREVIOUS` по календарю.
- Не считай успешный запуск backend доказательством, что все токены переведены на новый ключ.
- Не теряй старый ключ: он нужен для старых токенов и резервных копий БД.
- Не меняй ключ во время инцидента обновления Pinterest refresh token.
- Не запускай массовую запись/перешифровку на production без проверенного staging-процесса и backup.

## Плановая ротация

1. Убедись, что действующий ключ и предыдущий ключ (если есть) сохранены в независимом защищённом vault. Доступ к vault должен иметь назначенный recovery-оператор.
2. Создай новый криптографически случайный ключ ровно 32 байта. Храни его как secret, не как текст в репозитории.
3. В staging выставь новый ключ в `PINTEREST_TOKEN_ENCRYPTION_KEY`, а прежний active key — в `PINTEREST_TOKEN_ENCRYPTION_KEY_PREVIOUS`.
4. Проверь на тестовом аккаунте: чтение старого токена, запись нового токена, OAuth refresh, повторный read, CAS-конфликт. Используй тестовые credentials.
5. Перед production изменением создай согласованную резервную копию БД и зафиксируй соответствующий набор ключей в vault.
6. Через secret manager обнови production variables. Не удаляй previous key.
7. Проверь запуск backend и контролируемое чтение тестового/разрешённого аккаунта. При ошибке расшифровки останови ротацию и восстанови согласованную пару ключей.
8. Дай lazy migration время, но не устанавливай срок автоматического удаления previous key: неактивные аккаунты могут не читаться.
9. До вывода старого ключа нужен отдельный read-only scan всех ненулевых access/refresh ciphertexts: active key должен успешно расшифровать каждую запись. Отчёт содержит только aggregate counts/errors, никогда не сами токены.
10. Повтори scan после сверки конкурентных OAuth refresh/update. Сохрани результат вне production.
11. Оставь старый ключ в escrow на весь срок хранения backup-наборов, которые могут содержать шифротексты под этим ключом.

## При потере ключа или массовой ошибке расшифровки

1. Приостанови Pinterest refresh/disconnect и любые операции записи токенов.
2. Не удаляй и не перезаписывай строки с ciphertext.
3. Восстанови exact key pair из vault для соответствующего backup snapshot.
4. Восстанови БД в отдельный проект и проверь расшифровку до переключения production.
5. Если ключ восстановить невозможно, ciphertext нельзя расшифровать; пользователям потребуется повторно подключить Pinterest после восстановления сервиса.

## Текущий статус на 2026-11-11

- Lazy re-encryption реализован; он запускается при чтении аккаунта.
- Формат `enc:v1` не содержит ID ключа.
- Автоматического полного inventory/retirement gate в репозитории не найдено.
- Live key escrow и фактическое состояние production rows не проверялись.
- Не удалять previous key до появления и успешного выполнения отдельной read-only проверки.
