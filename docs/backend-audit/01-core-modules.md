## Проверенные файлы

| Файл | Назначение по коду | Результат просмотра |
|---|---|---|
| `backend/devTopup.js` | Валидация dev-пополнения кредитов | Запрет в production; требуется явный флаг и секрет длиной не менее 32 символов; сравнение секрета через `timingSafeEqual`; сумма ограничена 1–100000. Сам маршрут и конфигурация окружения требуют отдельной проверки. |
| `backend/publicUrl.js` | Защита исходящих запросов к URL пользователя от SSRF | DNS-адреса проверяются; private/special-use IP блокируются; lookup закрепляется за проверенным hostname. Нужны тесты граничных IPv6/IPv4-форм и проверка всех callers. |
| `backend/validate.js` | Общие валидаторы | Email/password/int/enum/url валидируются; `validateUrl` ограничивает схему HTTP(S), но не заменяет SSRF-защиту — callers, выполняющие сетевые запросы, должны использовать `publicUrl.js`. |
| `backend/admin.js` | Проверка admin и агрегаты статистики | Проверка роли выполняется по `users.is_admin`; выборки постраничные. Метрики `creditsSoldByMonth` суммируют все положительные строки `credit_transactions`, а не явно только продажи: требуется сверить семантику типов ledger перед использованием как финансовой выручки. |
| `backend/tariff.js` | Серверная проверка тарифных прав | Проверяет актуальную успешную подписку, fail-closed при ошибке чтения; неизвестные тарифы не входят в список генерационных тарифов. Отдельно проверить согласованность с webhook/продлением и миграциями. |
| `backend/pinterestOAuth.js` | Нормализация срока жизни токена | Проверяет конечное положительное число секунд и корректность итоговой даты. |
| `backend/pinterestTokenCrypto.js` | Шифрование Pinterest-токенов | AES-256-GCM, 12-byte IV, 16-byte tag; строгая проверка 32-byte ключа; поддержка предыдущего ключа для ротации; legacy plaintext пока читается — нужна проверка миграционного пути и production-конфигурации. |
| `backend/pinterestRefreshRecovery.js` | Разбор результата refresh токена | Успешное обновление подтверждается сменой обеих частей credential pair и снятием uncertainty fence; 429 отделён от неоднозначных сетевых/5xx ошибок. Проверить callers и integration сценарии. |

## Подтверждённые дефекты

На основании только этих восьми файлов **критический дефект не подтверждён**. Найдена одна зона риска для проверки:
- Админская метрика называется `creditsSoldByMonth`, но сейчас включает все положительные `credit_transactions.amount`; пока не изучены все типы ledger и UI-назначение поля, нельзя считать её достоверной метрикой продаж или выручки.

Это не утверждение, что остальной backend безопасен или готов к production.
