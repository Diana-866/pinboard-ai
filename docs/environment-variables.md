# Переменные окружения PinPosy

Документ составлен по фактическим обращениям к process.env в backend на ветке infra/postgresql-s3-migration. Значения секретов сюда не включаются.

## Где хранятся настройки
- Backend (Render или будущий сервер): переменные из раздела Backend. Секреты задаются только в защищённых настройках сервера.
- Frontend (Vercel / Vite): только публичные переменные с префиксом VITE_. Сейчас приложению нужен VITE_API_URL.
- Не копировать backend-секреты во frontend, исходники или GitHub Actions.
- Не отправлять значения секретов в чат и не добавлять реальные .env-файлы в Git.

## Backend: основные настройки
| Переменная | Назначение | Чувствительность |
|---|---|---|
| SUPABASE_URL | URL проекта Supabase для БД и Storage | Публичный адрес инфраструктуры |
| SUPABASE_SERVICE_ROLE_KEY | Привилегированный серверный ключ Supabase | Критичный секрет |
| JWT_SECRET | Подпись пользовательских JWT и Pinterest OAuth state | Критичный секрет |
| GPTUNNEL_API_KEY | Авторизация запросов генерации текста и изображений | Критичный секрет |
| FRONTEND_URL | Разрешённые CORS origins и адрес фронтенда для писем, оплаты и возвратов; допускает несколько origins через запятую | Не секрет, влияет на redirect/CORS |
| PORT | Порт HTTP-сервера; обычно задаётся хостингом | Служебная |

В backend/supabase.js предусмотрен fallback на SUPABASE_ANON_KEY, если service-role ключ не задан. Для backend следует настроить SUPABASE_SERVICE_ROLE_KEY; anon key не является полноценной заменой привилегированного серверного ключа.

## Backend: Prodamus
| Переменная | Назначение | Чувствительность |
|---|---|---|
| PRODAMUS_SHOP_ID | Идентификатор магазина; проверяется при определении конфигурации платежей | Идентификатор |
| PRODAMUS_SECRET | Подпись исходящих платёжных ссылок; fallback для проверки webhook | Критичный секрет |
| PRODAMUS_SECRET_WEBHOOK | Отдельный секрет входящих webhook; если задан, используется вместо общего секрета | Критичный секрет |
| PRODAMUS_URL | Адрес платёжной формы; по умолчанию используется адрес payform PinPosy | Публичный URL |
| PRODAMUS_SYS | Необязательный системный параметр запроса создания ссылки | Зависит от значения |
| PRODAMUS_DEMO | Включает demo_mode при значении 1 или true | Тестовый режим |
| PRODAMUS_OFFLINE | При значении 1 собирает ссылку локально без сетевого запроса | Только локальные тесты |

Для production использовать реальные реквизиты магазина и отдельно проверить webhook в кабинете Prodamus. Не включать PRODAMUS_DEMO и PRODAMUS_OFFLINE в рабочем окружении.

## Backend: почта
| Переменная | Назначение | Чувствительность |
|---|---|---|
| MAIL_SMTP_HOST | SMTP-сервер отправки писем | Адрес сервера |
| MAIL_SMTP_PORT | SMTP-порт; по умолчанию 465 | Служебная |
| MAIL_IMAP_HOST | IMAP-сервер чтения входящих писем в админке | Адрес сервера |
| MAIL_IMAP_PORT | IMAP-порт; по умолчанию 993 | Служебная |
| MAIL_USER | Почтовый логин | Конфиденциальные данные |
| MAIL_PASS | Пароль или пароль приложения почтового ящика | Критичный секрет |
| MAIL_FROM | Необязательный адрес отправителя; по умолчанию MAIL_USER | Публичный адрес |

SMTP нужен для подтверждения регистрации, восстановления пароля и системных писем. IMAP нужен только для чтения входящих писем в админке; если эта функция не используется, IMAP-переменные не обязательны.

## Backend: Pinterest OAuth
| Переменная | Назначение | Чувствительность |
|---|---|---|
| PINTEREST_CLIENT_ID | Идентификатор приложения Pinterest | Идентификатор |
| PINTEREST_CLIENT_SECRET | Секрет приложения Pinterest | Критичный секрет |
| PINTEREST_REDIRECT_URI | Точный callback URL, зарегистрированный в Pinterest Developer Portal | Публичный URL |

Если эти три переменные не заданы, Pinterest-интеграция отключена, остальные функции могут работать.

## Backend: дополнительные настройки
| Переменная | Назначение | Рекомендация |
|---|---|---|
| PUBLIC_BACKEND_URL | Публичный адрес backend для webhook и ссылок возврата; приоритетнее BACKEND_URL | Указать публичный HTTPS URL |
| BACKEND_URL | Запасной адрес backend, если PUBLIC_BACKEND_URL не задан | Использовать только при необходимости |
| NODE_ENV | Определяет production-поведение | На рабочем сервере установить production |
| ADMIN_SECRET | Защищает тестовое пополнение кредитов | Секрет; dev-маршрут не включать в production |
| ENABLE_DEV_TOPUP | Разрешает тестовое пополнение только вне production при значении true | Не задавать в production |
| ALLOW_TARIFF_SELF_SELECT | Управляет ручным выбором тарифа в dev-сценарии | Не задавать в production |

## Frontend (Vite / Vercel)
| Переменная | Назначение | Чувствительность |
|---|---|---|
| VITE_API_URL | Публичный базовый URL API; production адрес сейчас https://api.pinposy.com | Публичная |

Любая переменная VITE_* встраивается в клиентскую сборку и доступна посетителям сайта. Секреты с таким префиксом размещать запрещено.

## Минимальный production-чек-лист
1. Настроить SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, JWT_SECRET и GPTUNNEL_API_KEY.
2. Настроить FRONTEND_URL и публичный URL backend (предпочтительно PUBLIC_BACKEND_URL).
3. Настроить Prodamus и отдельно проверить webhook.
4. Настроить SMTP и проверить регистрацию, подтверждение email и восстановление пароля.
5. Добавить Pinterest credentials только если OAuth-публикация включается в релиз.
6. Установить NODE_ENV=production; не задавать dev/test-переменные.
7. Во frontend задать только VITE_API_URL=https://api.pinposy.com.

## Ограничения проверки
Документ не подтверждает, какие переменные уже заданы в аккаунтах Render, Vercel, Supabase, Prodamus или у почтового провайдера: доступ к их настройкам отдельно не проверялся.
Не запускать миграции БД и не менять production-переменные до проверки текущего состояния и резервной копии.
