## Дни 3–4. Развёртывание

- Память на 4 ГБ. Минимальный набор Supabase (берётся из официального self-hosted compose, лишнее отключается): **нужны** `db` (Postgres), `kong` (шлюз), `rest` (PostgREST — весь доступ бэкенда к данным идёт через него), `auth` (GoTrue — регистрация/вход), `storage` (Storage API — картинки пинов). **Отключаются** `studio` (веб-админка базы), `meta`, `analytics` (Logflare), `vector`, `realtime` (не используется), `imgproxy` (преобразование картинок не используется), `functions` (Edge Functions не используются), `supavisor`/pooler (PostgREST ходит напрямую). Оценка: Supabase ≈ 800–1300 МБ (db 300–500, kong 120–180, rest 60–100, auth 40–80, storage 80–150), наш стек ≈ 600–900 МБ (backend 150–250, два воркера по 60–100, Caddy 30–60, остальное — Node), ОС ≈ 400–600 МБ. Итого ≈ 1,8–2,6 ГБ, запас 1,4–2,2 ГБ. **Не проверено:** цифры оценочные, реальные измеряются на сервере (`docker stats --no-stream`, `free -h`).
- Запасной вариант, если 4 ГБ не хватит (по порядку): 1) отключить `storage` и перейти на хранение картинок на диске сервера раздачей через Caddy (`/media`) — минус 80–150 МБ и минус зависимость; 2) вынести `db` в отдельную managed-базу провайдера, на VPS останутся только лёгкие сервисы; 3) доплатить за 8 ГБ у того же провайдера (обычно +300–600 ₽/мес) — самый простой путь, решение владельца. Своп включать не будем: Postgres на свопе превращается в зависания вместо ошибок.
