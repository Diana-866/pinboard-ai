# AUD-170 — Автосохранение описания пина

Дата: 2026-11-08

## Обнаруженная проблема
Описание пина обновлялось в React state при каждом вводе, но запрос PATCH отправлялся только при потере фокуса textarea. При долгом редактировании и закрытии/переключении страницы до завершения сохранения последние введённые изменения могли остаться только в памяти интерфейса. У поля также не было явного статуса сохранения.

## Исправление
- Добавлено автоматическое сохранение описания через 800 мс после последнего ввода.
- При потере фокуса отложенный таймер отменяется и запускается немедленное сохранение.
- Используется существующая сериализация PATCH-запросов по ID пина, поэтому сохранения одного пина выполняются последовательно.
- В интерфейсе отображаются статусы «Сохранение…», «Сохранено» и «Не сохранено — проверьте соединение».
- Добавлен revision guard: завершение старого запроса не может перезаписать индикатор более нового редактирования.

## Проверка
- Проверено наличие debounce, немедленного сохранения на blur, использования persistPinPatch и revision guard в исходном коде.
- Полный TypeScript lint, Vite build и браузерные тесты не запускались в этой сессии.
- Не изменялись backend, схема БД, Supabase Storage, production data; не выполнялись деплой и merge.

## Эффект для пользователя
Описание начинает сохраняться автоматически, не нужно специально кликать за пределы поля. Пользователь видит, завершилось ли сохранение; если сервер не принял изменения, интерфейс не показывает ложное «Сохранено».
