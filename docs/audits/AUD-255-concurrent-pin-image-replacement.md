# AUD-255 — защита от гонки при одновременной замене изображения пина

**Дата:** 2026-11-09  
**Endpoint:** POST /pins/:id/image

## Проблема

Маршрут загружал новый объект в Storage, затем безусловно обновлял pins.image_url по id и board_id. Два параллельных запроса могли оба прочитать старый URL, оба загрузить свои объекты и последовательно перезаписать строку. Это создавало lost update: более ранний запрос, завершившийся позже, мог затереть более новую картинку. При этом каждый запрос пытался удалить только URL, прочитанный до загрузки, поэтому объект проигравшей загрузки мог остаться неиспользуемым.

## Исправление

- Добавлен compare-and-swap фильтр: UPDATE дополнительно требует, чтобы image_url всё ещё совпадал с исходным значением.
- Если исходное значение NULL, используется PostgREST IS NULL, а не EQ NULL.
- UPDATE использует maybeSingle: отсутствие обновлённой строки считается конкурентным конфликтом.
- При конфликте новый объект удаляется через существующий reference-aware deletion protocol; при отказе cleanup ошибка логируется, не подменяя исходный конфликт.
- Клиент получает HTTP 409 и понятное предложение обновить карточку и повторить загрузку.

## Регрессионные тесты

Добавлены тесты выбора EQ для существующего URL и IS NULL для пустого image_url. Тест подключён к atomic-payment-integration workflow.

## Проверки и ограничения

- Код и тесты записаны в feat/persisted-boards-api.
- Статический read-back и CI run ещё предстоит выполнить.
- Node unit tests и реальный конкурентный HTTP-тест локально не запускались.
- Production, Supabase Storage, БД, deployment и merge не затрагивались.
