# AUD-238 — гонки отмены и публикации Pinterest (2026-11-09)

## Проверенная защита
- API отмены выполняет условный UPDATE только для `status='scheduled'`. Это точка линеаризации отмены: если отмена фиксируется первой, функция захвата не видит запись в очереди.
- Worker атомарно переводит запись в `publishing` и выдаёт `claim_token`. После этого условная отмена не должна затронуть строку или очистить токен.
- Смена доски доступна только для `failed`; сервер вызывает `change_failed_pin_schedule_board`, где проверка текущего статуса и изменение выполняются в БД. При переходе расписания в другое состояние RPC должен отказать. До RPC backend также перепроверяет аккаунт и доску.
- Worker completion/failure updates ограждены статусом `publishing`, полной identity и точным `claim_token`.

## Изменения продукта
- В `POST /schedule/:id/cancel` устранена неверная семантика ответа: если условный UPDATE не изменил строку, backend перечитывает запись того же пользователя. Отсутствующая/чужая запись даёт 404; существующая запись в другом состоянии — 409 Conflict с понятным сообщением для `publishing`, `published`, `cancelled` или иного перехода.
- Повторное чтение не меняет запись и не пытается отменить уже захваченную worker задачу. Оно только объясняет пользователю, почему действие не выполнено.

## Regression test
- Добавлен `backend/test/pinterest-schedule-cancellation-race.integration.sql` и подключён в atomic-payment integration workflow.
- Сценарий A: отмена первой — последующий `claim_due_pin_schedules` не возвращает cancelled schedule.
- Сценарий B: worker claim первым — отмена с тем же условием `status='scheduled'` не обновляет строку; статус остаётся `publishing`, fencing token остаётся непустым.
- Тест использует отдельные fixtures и выполняется в транзакции с rollback.

## Пользовательский эффект
Пользователь получает правильное объяснение вместо ложного «не найдено», когда публикация уже началась. И главное — запрос отмены не перезаписывает состояние задания, которым владеет worker, а ранняя отмена не позволяет worker начать публикацию.

## Статус
- Код и regression SQL записаны в feature branch; статический read-back требуется после последних коммитов.
- Локальная PostgreSQL среда не подключена, тест фактически не запускался; требуется CI.
- Production DB, Pinterest API, deployment и merge не затрагивались.
