# AUD-254 — ограничение multipart-запроса загрузки изображений

**Дата:** 2026-11-09  
**Область:** backend upload endpoint POST /pins/:id/image

## Найденная проблема

Multer ограничивал размер бинарного файла (5 МиБ), но не задавал пределы для количества и размера дополнительных текстовых полей и общего количества multipart-частей. Endpoint не использует эти поля для сохранения изображения. Поэтому авторизованный клиент мог отправлять крупные/многочисленные ненужные поля и создавать избыточную нагрузку на память и обработку запроса.

## Исправление

- files: 1 — не более одного файла.
- fields: 10 и fieldSize: 16 * 1024 — не более десяти дополнительных полей по 16 КиБ каждое.
- parts: 11 — согласованный общий предел частей (одно изображение + десять полей).
- Существующий предел изображения 5 МиБ сохранён.
- Известные Multer ошибки LIMIT_FIELD_VALUE, LIMIT_FIELD_COUNT, LIMIT_PART_COUNT и LIMIT_FILE_COUNT возвращаются как понятные JSON-ответы 413/422.
- Неизвестные middleware ошибки не маскируются и передаются Express.

## Регрессии

В backend/test/image-upload-errors.test.js добавлена проверка отображения новых кодов Multer в клиентские статусы. Существующий workflow запускает этот тест после установки backend зависимостей.

## Проверки и ограничения

- Изменения внесены непосредственно в feat/persisted-boards-api.
- Статический read-back и CI run для этого коммита ещё предстоит выполнить.
- Node-тесты и HTTP multipart integration test локально не запускались.
- Production, Supabase Storage, база данных, deployment и merge не затрагивались.
