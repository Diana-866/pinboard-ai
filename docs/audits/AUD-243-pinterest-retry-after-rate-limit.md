# AUD-243 — учитывать Retry-After Pinterest при безопасном повторе (2026-11-09)

## Найдено
Общий Pinterest request wrapper повторял GET после HTTP 429 через фиксированные 2 секунды. Pinterest может вернуть заголовок Retry-After в секундах или HTTP-date; игнорирование этого значения приводит к повторному запросу раньше разрешённого срока и может продлить rate limit.

## Исправлено
- Добавлен чистый helper `getPinterestRetryDelayMs`: понимает Retry-After в секундах и HTTP-date, использует fallback 2 секунды при отсутствующем/некорректном значении, ограничивает ожидание 60 секундами и не допускает отрицательное ожидание.
- `callPinterest` передаёт рассчитанную задержку только для ответа 429.
- `executeWithAccountToken` использует задержку ответа вместо фиксированной паузы; повтор по-прежнему ограничен одной попыткой.
- Неидемпотентный POST публикации по-прежнему вызывает wrapper с `retryRateLimit:false`: после 429 он не повторяется автоматически, потому что нельзя допустить дублирующий пин.
- Добавлены unit regressions на секунды, HTTP-date, прошлую дату, некорректный заголовок, верхнюю границу и фактическое использование задержки.
- В atomic-payment workflow добавлен отдельный Node test step для этого тестового файла.

## Пользовательский эффект
При ограничении Pinterest PinPosy будет ждать указанный Pinterest срок (в пределах 60 секунд), а не повторять чтение досок преждевременно через фиксированные две секунды. Публикация пина не получает автоматический повтор после 429 — защита от дубликатов сохранена.
