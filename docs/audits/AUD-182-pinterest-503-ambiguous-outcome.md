# AUD-182 — Не считать Pinterest HTTP 503 безопасным отказом публикации

**Дата:** 2026-11-08  
**Область:** `backend/pinterest.js`, `backend/pinterestSchedule.js`, `backend/test/pinterest-schedule.test.js`.

## Найденная проблема

В ветке обработки исключения вокруг `withAccount(... callPinterest(POST /pins))` статус HTTP 503 входил в список ошибок, которые помечали попытку как `failed` с `retry_safe=true`. При этом обычный ответ Pinterest с HTTP 5xx в соседней ветке уже считался неоднозначным. Это противоречие опасно: промежуточный шлюз может вернуть 503 после того, как удалённый сервис успел обработать POST. Разрешение повтора в такой ситуации способно создать второй пин.

## Исправление

- В `backend/pinterestSchedule.js` добавлен единый чистый предикат `isPinterestPublishOutcomeUnknown`.
- Только явные клиентские отказы 400/401/403/404/409/422 считаются подтверждённым отказом без созданного пина.
- Все 5xx, таймауты/неизвестные статусы и отсутствие корректного HTTP-статуса считаются неоднозначным исходом.
- `backend/pinterest.js` использует этот предикат в catch-ветке и передаёт `p_outcome_unknown=true` для HTTP 503 и других серверных ошибок. Такая попытка не получает разрешение на автоматический повтор.
- Добавлены два регрессионных теста: 5xx не разрешают повтор, явные 4xx-отказы классифицируются как безопасные.

## Эффект для пользователя

Если Pinterest или промежуточный сервер вернёт 503 после запроса публикации, PinPosy не будет автоматически отправлять тот же пин второй раз. Запись останется требующей сверки, пока исход первой попытки не станет понятен. Это безопаснее, чем риск незаметно создать дубликат.

## Проверка и ограничения

- Два изолированных теста нового классификатора выполнены на Node.js 22: **2 passed, 0 failed**.
- Полный `backend/test/pinterest-schedule.test.js`, весь backend suite и production-интеграция не запускались.
- Перед фиксацией дополнительно проверено, что helper импортируется в `backend/pinterest.js` и вызывается в нужной catch-ветке.
- Изменения находятся в `feat/persisted-boards-api`, PR #4 Draft. Миграции, production и deployment не затрагивались.
