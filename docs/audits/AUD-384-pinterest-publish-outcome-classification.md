# AUD-384 — единая классификация неуспешных ответов Pinterest при публикации

**Дата:** 2026-11-11  
**Статус:** исправление и регрессионное покрытие внесены в feature branch.

## Обнаруженная несогласованность

В `publishPin` два пути обработки ошибки POST /pins использовали разные правила:

- thrown/network path вызывал общий `isPinterestPublishOutcomeUnknown(status)`;
- returned HTTP response path вручную считал неоднозначными только 408, 429 и 5xx.

Общий предикат считает безопасными только явно перечисленные клиентские отказы 400/401/403/404/409/422. Поэтому неожиданный HTTP 3xx попадал в returned-response ветке в безопасный отказ и мог получить разрешение на повтор, тогда как тот же статус в thrown path был бы неоднозначным. Это создавало расхождение в защите от дублирующей публикации.

## Исправление

- Обе ветки теперь используют `isPinterestPublishOutcomeUnknown`.
- Удалено локальное частичное условие `408 || 429 || >= 500`.
- Расширен unit regression: 0, 3xx, 408, 429, 5xx и некорректный статус должны оставаться неоднозначными.
- Явный allowlist клиентских отказов 400/401/403/404/409/422 остаётся отдельным тестом.

## Поведение

- 401 может один раз запустить обновление токена через account request wrapper; после повторного отказа POST не повторяется бесконечно.
- 403 и остальные явные client rejections не считаются созданием пина.
- 408, 429, 5xx, неизвестный статус и неожиданные 3xx не разрешают автоматическую повторную публикацию.
- Для POST /pins автоматический повтор по 429 по-прежнему отключён.

## Проверки и ограничения

- Изменённые файлы перечитаны через GitHub API.
- Node test, backend suite, lint и deployment не запускались в этой среде.
- Реальные Pinterest API, production database, платежи и пользовательские публикации не затрагивались.
