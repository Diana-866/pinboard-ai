# AUD-384 — единая классификация неуспешных ответов Pinterest при публикации

**Дата:** 2026-11-11  
**Статус:** исправление и регрессионное покрытие внесены в feature branch.

## Обнаруженная несогласованность

В `publishPin` два пути обработки ошибки POST /pins использовали разные правила: thrown/network path вызывал общий `isPinterestPublishOutcomeUnknown(status)`, а returned HTTP response path вручную считал неоднозначными только 408, 429 и 5xx. Поэтому неожиданный HTTP 3xx попадал в response-ветке в безопасный отказ и мог получить разрешение на повтор, хотя общий классификатор считает его неоднозначным.

## Исправление

- Обе ветки теперь используют `isPinterestPublishOutcomeUnknown`.
- Удалено локальное частичное условие `408 || 429 || >= 500`.
- Unit regression охватывает 0, 3xx, 408, 429, 5xx и некорректный статус.
- Явный allowlist клиентских отказов 400/401/403/404/409/422 остаётся отдельным тестом.

## Поведение

401 может один раз запустить обновление токена; после повторного отказа POST не повторяется бесконечно. 403 и другие явные client rejections не считаются созданием пина. 408, 429, 5xx, неизвестный статус и неожиданные 3xx не разрешают автоматическую повторную публикацию. Для POST /pins автоматический повтор по 429 отключён.

## Проверки и ограничения

Изменённые файлы перечитаны через GitHub API. Node test, backend suite, lint и deployment не запускались. Реальные Pinterest API, production database, платежи и пользовательские публикации не затрагивались.
