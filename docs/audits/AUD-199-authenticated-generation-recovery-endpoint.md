# AUD-199 — Авторизованный просмотр результата генерации для восстановления

## Проблема
Браузер сохраняет отдельные idempotency keys для разных запросов. Если пользователь меняет тему, доску или настройки после сбоя, fingerprint меняется и прежний ключ не выбирается автоматически. Сервер уже хранит состояние запроса и завершённые пины, но у frontend не было безопасного read-only API, чтобы проверить старую операцию без повторной генерации.

## Исправление
- Добавлен авторизованный `GET /generation/requests/:key`.
- Запрос ищется одновременно по `req.userId` и idempotency key: знание чужого ключа не даёт доступ к чужой генерации.
- Endpoint не принимает новую тему/параметры и не запускает провайдера, не резервирует кредиты и не меняет состояние операции.
- Для завершённой генерации возвращаются только пользовательские поля сохранённых пинов.
- Для незавершённых/неопределённых/неуспешных операций возвращается статус без частичных результатов.
- Provider prompts, task IDs, токены и внутренние ошибки не выдаются.
- Формат ответа вынесен в `backend/generationRecovery.js`, добавлены unit tests на allowlist полей, скрытие незавершённых результатов и нормализацию неожиданного статуса.

## Изменённые файлы
- `backend/index.js`
- `backend/generationRecovery.js`
- `backend/test/generation-recovery.test.js`

## Пользовательский эффект
Это серверная основа для следующего шага интерфейса восстановления: frontend сможет проверить ранее сохранённый ключ после изменения параметров или перезагрузки и показать уже готовые пины, не отправляя новый платный запрос. Сам endpoint уже доступен только авторизованному владельцу, но интерфейс автоматического поиска и выбора незавершённых операций ещё предстоит подключить.

## Проверки и ограничения
Добавлены unit tests, но запуск backend test suite не подтверждён в этой среде. Endpoint не требует новой миграции: использует существующую `pin_generation_requests`. Production, рабочая БД и деплой не затрагивались.
