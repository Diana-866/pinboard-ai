# AUD-186 — Безопасное восстановление расписания после OAuth reconnect

**Дата:** 2026-11-08  
**Область:** Pinterest account identity и ручной retry расписаний  
**Статус:** regression test добавлен в feature-ветку; production не затронут.

## Что проверено и улучшено

При отключении Pinterest-профиля будущие задания переводятся в failed. OAuth reconnect того же внешнего Pinterest identity повторно использует стабильный `pinterest_accounts.id`, но старые задания не должны автоматически переходить обратно в очередь: пользователь мог отключить профиль намеренно, а автоматический запуск после повторного входа был бы неожиданным действием.

В `backend/test/pinterest-account-publication.integration.sql` добавлен сценарий:

1. Создаётся будущее расписание без зарезервированной попытки публикации.
2. Профиль отключается; расписание становится `failed`.
3. Тот же профиль повторно подключается, сохраняя прежний account UUID.
4. Проверяется, что расписание остаётся `failed` и не запускается автоматически.
5. Явный `retry_failed_pin_schedule` после reconnect переводит безопасное задание обратно в `scheduled`.

## Результат

Повторное подключение аккаунта не публикует старые задания неожиданно. Пользователь может сам решить, возобновлять ли публикацию. Повтор разрешается только если журнал не содержит ни одной попытки создания пина; неоднозначные публикации остаются заблокированными существующей защитой.

- Полные backend/frontend тесты не запускались.
