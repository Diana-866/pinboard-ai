# AUD-197 — Независимое восстановление нескольких генераций

## Проблема
В браузере хранилась только одна активная identity генерации. Новая генерация могла затереть ключ незавершённой операции, а успешное завершение одной операции очищало общий ключ. Это создавало риск, что после сетевого сбоя пользователь не восстановит прежний запрос и отправит новый платный запрос вместо повтора с прежним idempotency key. Общая запись также создавала конкуренцию между вкладками.

## Исправление
- Перешли на отдельный localStorage key для каждого compact request fingerprint.
- Чтение, восстановление и очистка теперь адресованы конкретному fingerprint.
- Успешная генерация удаляет только собственную запись.
- Другие незавершённые запросы остаются доступными после reload/browser restart.
- Добавлен поиск tab-scoped v2 записи, если localStorage недоступен.
- Старый единый sessionStorage формат мигрируется в scoped format; raw fingerprint нормализуется в compact fingerprint.
- Fingerprint не содержит исходную тему и настройки. Серверная проверка полного запроса остаётся авторитетной.

## Изменённые файлы
- `frontend/src/utils/pendingGenerationRequest.ts`
- `frontend/src/utils/pendingGenerationRequest.test.ts`
- `frontend/src/components/pins/PinGenerator.tsx`

## Проверки
Добавлены unit tests на независимые ключи двух запросов, выборочную очистку, восстановление после сброса памяти, миграцию legacy sessionStorage, compact fingerprint и blocked storage fallback.

Тесты не запускались в этой среде: локального checkout репозитория и установленных frontend dependencies нет. Требуется дождаться GitHub Actions на новом HEAD.

## Влияние для пользователя
Если генерация A зависла из-за потери ответа, а пользователь затем запускает генерацию B, сохранённый ключ A больше не затирается ключом B. Успешное завершение B также не удаляет возможность восстановить A. Это снижает риск повторного платного запуска и потери уже созданной сервером задачи.

## Ограничения
- Хранилище браузера не является серверным журналом; очистка данных сайта или другого браузерного профиля удалит клиентскую копию.
- Серверная идемпотентность и журнал задач остаются обязательной защитой.
- Миграции БД, production и деплой не затрагивались.
