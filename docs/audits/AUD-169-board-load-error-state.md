# AUD-169 — Ошибка загрузки досок не должна выглядеть как удаление данных

Дата: 2026-11-08

## Обнаруженная проблема
В `frontend/src/App.tsx` загрузка досок из `GET /boards` при любой сетевой/API-ошибке завершалась вызовом `setBoards([])`. Компонент `BoardsManager` трактовал пустой массив как реальное отсутствие досок и показывал обычное состояние «досок пока нет». При временном сбое сети пользователь мог решить, что его сохранённые доски пропали, и начать создавать дубликаты.

## Исправление
- Добавлено отдельное состояние `boardsLoadError`.
- При смене пользователя локальный список очищается перед загрузкой, чтобы не показывать данные предыдущей сессии.
- При ошибке `GET /boards` ошибка сохраняется отдельно; результат не маскируется под успешную пустую загрузку.
- `BoardsManager` теперь показывает явное предупреждение об ошибке загрузки и сообщает, что доски не удалены. Состояние «досок нет» показывается только при успешной загрузке пустого списка.
- Ошибка не запускает автоматическое повторное создание досок и не меняет серверные данные.

## Проверка
- Повторно прочитаны изменённые файлы через GitHub Contents API.
- Source checks: состояние ошибки присутствует в App, передаётся в BoardsManager, UI проверяет ошибку до отображения empty state.
- Полный TypeScript/Vite build и браузерный E2E в этой сессии не запускались. Требуется полноценный CI run; предыдущие CI failures без шагов runner не считаются проверкой.
- Production, Supabase и Storage не затрагивались; миграции не применялись; деплой и merge не выполнялись.

## Эффект для пользователя
Если сервер временно недоступен, экран досок больше не утверждает, что список пуст. Пользователь видит, что загрузка не удалась и его доски не удалены, поэтому меньше риск принять временный сбой за потерю данных.
