# AUD-256 — криптографические адреса изображений и CI lifecycle tests

Дата: 2026-11-09  
Ветка: `feat/persisted-boards-api`

## Что обнаружено

Обычные загружаемые изображения получали object path вида `timestamp + Math.random()`. `Math.random()` не является криптографическим генератором. Хотя публичные URL изображений не являются секретами доступа, предсказуемые имена облегчают перебор адресов публичного bucket и не подходят как стандарт генерации идентификаторов для пользовательских объектов.

Также существовал отдельный пробел покрытия: `backend/test/pin-image-lifecycle.test.js` содержал проверки резервирования, безопасного удаления, неоднозначных ошибок Storage и fencing, но GitHub Actions workflow не запускал этот файл.

## Что исправлено

- Для новых обычных загрузок случайная часть имени генерируется через `crypto.randomBytes(16)`: 128 бит криптографической энтропии.
- Временная метка сохранена для удобства диагностики.
- Валидатор managed object path расширен до 32 hex-символов, при этом старые имена с коротким случайным суффиксом остаются распознаваемыми.
- Добавлен тест формата, уникальности независимых имён и совместимости нового пути с безопасным извлечением managed path.
- В workflow добавлен отдельный шаг запуска `node --test backend/test/pin-image-lifecycle.test.js`.

## Пользовательский эффект

Новые имена изображений существенно сложнее предсказать. Существующие объекты и deterministic generation keys не меняются. Важные проверки жизненного цикла Storage теперь входят в PR CI, а не остаются неисполняемым набором тестов.

## Проверка и ограничения

- Изменения записаны в GitHub и будут повторно прочитаны для статической проверки.
- Локальные Node-тесты в этой среде не запускались.
- Фактический результат CI для нового HEAD проверяется отдельно; до успешного запуска считать тесты неподтверждёнными.
- Production, Supabase Storage, база данных, deployment и merge не затрагивались.
