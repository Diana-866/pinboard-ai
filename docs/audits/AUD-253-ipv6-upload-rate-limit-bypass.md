# AUD-253 — защита лимита загрузки изображений от IPv6-ротации

**Дата:** 2026-11-09  
**Область:** rate limit `POST /pins/:id/image`

## Проблема

Лимитер использовал пользовательский `keyGenerator` со значением `req.userId || req.ip`. Для неавторизованного клиента это обходило IPv6-нормализацию, которую стандартный генератор `express-rate-limit` выполняет через `ipKeyGenerator`. Ротация адресов внутри одной IPv6-подсети могла создавать новые счётчики и ослаблять защиту от массовых загрузок.

## Изменения

- Добавлен `backend/pinImageRateLimitKey.js`.
- Авторизованные запросы получают ключ `user:<id>`, поэтому смена IP не сбрасывает их счётчик.
- Остальные запросы используют официальный `ipKeyGenerator` из `express-rate-limit@8.7.0`, закреплённого в `backend/package-lock.json`.
- Для отсутствующего IP используется общий fallback-ключ, а не отключается ограничение.
- Добавлен тест на IPv6 /56, раздельные подсети, стабильность user ID, IPv4 и fallback.
- CI устанавливает backend dependencies командой `npm ci --prefix backend` перед Node-тестами.

## Пользовательский эффект

Ротация IPv6-адресов внутри одной подсети не должна давать клиенту дополнительные лимиты загрузки. Для авторизованного аккаунта лимит остаётся стабильным при смене сети.

## Проверка

Изменения статически интегрированы в `backend/index.js`, тест добавлен в workflow. Фактическое выполнение Node-тестов и CI ещё не подтверждено. Production, Storage, БД, deployment и merge не затрагивались.
