# AUD-180 — Надёжная загрузка расписания и восстановление после сетевого сбоя

**Дата:** 2026-11-08  
**Область:** загрузка календаря публикаций в `frontend/src/App.tsx` и отображение ошибок в `frontend/src/components/calendar/PublishingCalendar.tsx`.

## Что было не так

Если запрос `GET /schedule` завершался сетевой или серверной ошибкой, приложение записывало пустой массив в `scheduledPins`. В результате календарь выглядел так, будто у пользователя нет публикаций, хотя данные в базе могли быть полностью целы.

Дополнительно некорректный ответ API (не массив) молча превращался в пустое расписание. Это скрывало нарушение контракта API и могло вводить пользователя в заблуждение.

## Что исправлено

### `frontend/src/App.tsx`

- Добавлены отдельные состояния `scheduleLoadError` и `scheduleReloadToken`.
- При смене пользователя список расписания очищается, чтобы не показать данные предыдущего аккаунта.
- При обычной повторной загрузке старые успешно загруженные записи сохраняются до получения нового ответа.
- Ошибка запроса больше не очищает `scheduledPins`; вместо этого сохраняется понятное сообщение об ошибке.
- Добавлена проверка контракта: ответ `/schedule` обязан быть массивом. Некорректный ответ считается ошибкой, а не пустым расписанием.
- Добавлен обработчик повторной загрузки без перезагрузки всей страницы.

### `frontend/src/components/calendar/PublishingCalendar.tsx`

- Добавлены необязательные props для ошибки и повторной загрузки.
- При ошибке показывается заметное предупреждение с текстом, что публикации не удалены.
- Добавлена кнопка «Загрузить снова».
- Пустое состояние календаря не подменяет собой ошибку загрузки.

## Что изменится для пользователя

- Если интернет пропадёт, календарь не будет выдавать сбой за отсутствие запланированных пинов.
- Если записи уже были загружены, они останутся видимыми при неудачной повторной загрузке.
- Пользователь сможет восстановить список кнопкой «Загрузить снова», не обновляя всю страницу.
- При некорректном ответе API приложение покажет ошибку вместо ложного пустого списка.
- После выхода или переключения аккаунта расписание предыдущего пользователя не останется на экране.

## Проверка и ограничения

- Изменения записаны в ветку `feat/persisted-boards-api`.
- Исходный код проверен на наличие отдельного состояния ошибки, retry token, проверки массива, сохранения данных при ошибке и очистки при смене пользователя.
- Полная сборка frontend, TypeScript-проверка и браузерные тесты не запускались.
