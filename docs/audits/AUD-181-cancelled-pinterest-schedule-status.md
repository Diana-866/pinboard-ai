# AUD-181 — Корректное отображение отменённых публикаций и неизвестных статусов

**Дата:** 2026-11-08  
**Область:** загрузка расписания в `frontend/src/App.tsx`, типы публикаций, календарь и локализации.

## Что было не так

Клиент преобразовывал статусы расписания цепочкой условий, а любое значение, которое не совпадало с `published`, `failed`, `publishing` или `unknown`, автоматически превращал в `scheduled`. При этом БД явно поддерживает состояние `cancelled` (миграции 015/017 и последующие). Поэтому отменённая запись могла отображаться как активная запланированная публикация. Любой будущий новый статус также ошибочно выглядел бы как запланированный.

## Что исправлено

- Добавлен `frontend/src/utils/scheduleStatus.ts` с единым разбором серверного статуса.
- Все известные статусы сохраняются без переинтерпретации; `cancelled` теперь является отдельным значением UI-модели.
- Неизвестные и некорректные значения переходят в безопасный статус `unknown`, а не в `scheduled`. Запись остаётся видимой и не получает доступных только запланированным публикациям действий.
- Календарь получил отдельный фильтр и нейтральную метку для отменённых публикаций.
- Добавлены переводы статуса отмены для всех семи языков приложения: en, ru, es, pt, de, fr, zh.
- Добавлены тесты на все шесть статусов БД и на неизвестные/некорректные значения.

## Что изменится для пользователя

- Отменённый пин больше не выглядит так, будто он всё ещё ждёт публикации.
- Его нельзя случайно отменить повторно через карточку расписания как активную запись.
- Если сервер начнёт возвращать новый статус, календарь покажет «Неизвестно», а не создаст ложное впечатление, что публикация запланирована.
- Пользователь сможет отдельно отфильтровать отменённые записи.

## Проверка и ограничения

- Изменения внесены в ветку `feat/persisted-boards-api`, PR #4; актуальный head проверяется отдельно после коммитов.
- Изолированный запуск двух тестов парсера на Node.js 22: **2 passed, 0 failed**. Это не полный frontend test suite.
- Полные `npm test`, `npm run lint` и `npm run build` не запускались; браузерная проверка не выполнялась.
- Миграции и production не затрагивались. Merge и deploy не выполнялись.
