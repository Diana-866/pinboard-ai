# AUD-252 — понятные ошибки загрузки изображения пина

**Дата:** 2026-11-09  
**Область:** backend multipart upload `POST /pins/:id/image`

## Проблема

Multer запускался как middleware до async обработчика маршрута. Поэтому превышение лимита файла возникало вне route try/catch и не преобразовывалось в ожидаемый JSON API-ответ. Неподдерживаемый MIME фильтр молча пропускал мимо `req.file`, после чего endpoint сообщал, будто файл вообще не передали. Сообщение также не перечисляло GIF, хотя формат уже поддерживается.

## Изменения

- Неподдерживаемый MIME теперь возвращает именованную ошибку `unsupported_image_type`.
- Добавлен сериализатор ошибок Multer:
  - 415 — неподдерживаемый формат;
  - 413 — превышение 5 МиБ;
  - 422 — неверное multipart-поле.
- Middleware возвращает структурированный JSON; неизвестные ошибки передаются в общий Express error handler.
- Сообщение об отсутствии файла перечисляет PNG/JPG/WebP/GIF и лимит 5 МиБ.
- Добавлены unit-регрессии; тесты подключены к существующему CI workflow.

## Проверка

Статически проверена интеграция helper в upload route и обновление CI-команды. Node tests и HTTP multipart smoke test в этой среде не запускались. CI-результат для нового HEAD ожидает проверки. Production, Storage, БД, deployment и merge не затрагивались.

## Пользовательский эффект

Пользователь получает понятное объяснение, что именно не так с загрузкой: формат, размер или поле формы. Ошибка большого файла больше не должна выглядеть как необъяснимая внутренняя ошибка сервера.
