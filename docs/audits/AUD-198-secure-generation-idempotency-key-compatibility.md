# AUD-198 — Совместимое создание безопасного ключа генерации

## Проблема
Frontend создавал ключ идемпотентности только через `crypto.randomUUID()`. В браузерах/встроенных webview, где UUID API отсутствует, генерация падала ещё до отправки запроса. Использовать `Math.random()` как запасной вариант нельзя: ключ должен быть непредсказуемым, иначе защита от повторной платной генерации становится слабее.

## Исправление
- Добавлен общий `createGenerationIdempotencyKey()`.
- Сначала используется `crypto.randomUUID()`, если он доступен.
- Если UUID API отсутствует, применяется `crypto.getRandomValues()` для 128 бит случайных данных.
- Если браузер не предоставляет криптографически безопасный генератор, операция завершается понятной ошибкой с просьбой открыть сайт через HTTPS. Небезопасный псевдослучайный fallback не используется.
- Оба места создания/ротации ключа в генераторе используют одну функцию.

## Проверки
Добавлены unit tests для предпочтения UUID, fallback на secure random bytes и отказа при отсутствии secure randomness. Тесты не запускались в локальном окружении: checkout и зависимости проекта здесь не установлены. CI для нового коммита ещё не подтверждён. Production и деплой не затрагивались.

## Пользовательский эффект
В браузере, где нет `crypto.randomUUID()`, генерация больше не должна ломаться только из-за отсутствия этого конкретного метода: используется поддерживаемый браузером криптографический генератор. Если безопасная случайность недоступна, PinPosy честно сообщает, что нужно открыть сайт через HTTPS, вместо создания слабого ключа.
