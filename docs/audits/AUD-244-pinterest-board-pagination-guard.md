# AUD-244 — надёжная загрузка большого списка Pinterest-досок (2026-11-09)

## Найдено
- Endpoint кабинета загружал максимум 8 страниц по 250 досок (2 000 записей). При большем количестве он возвращал общую ошибку 502, хотя Pinterest мог корректно отдавать следующие страницы.
- Код не проверял повтор bookmark/cursor. Если API или промежуточный ответ возвращал один и тот же курсор, запросы повторяли одну страницу до исчерпания лимита.
- Важно не возвращать частичный список как полный: пользователь может выбрать не ту доску или не увидеть нужную.

## Исправлено
- Вынесена пагинация в чистый helper `backend/pinterestBoardsPagination.js`.
- Лимит увеличен до 20 страниц по 250 записей (до 5 000 досок за запрос).
- Повторяющийся cursor обнаруживается до повторного HTTP-запроса; вместо бесконечного/повторного чтения возвращается явная ошибка.
- При исчерпании лимита helper явно сообщает, что список не был молча обрезан; частичный список не выдаётся как полный.
- Ошибка Pinterest (например, 429) возвращается без подмены на частичный результат.
- Добавлены unit regressions на полную пагинацию, повтор cursor, верхнюю границу и сохранение provider error.
- Новый Node test добавлен отдельным шагом в atomic-payment GitHub Actions workflow.

## Пользовательский эффект
Пользователь с большим числом Pinterest-досок сможет увидеть больше доступных досок (до 5 000 вместо прежних 2 000). Если Pinterest начнёт повторять cursor или досок окажется ещё больше, PinPosy покажет ошибку вместо тихо неполного списка или многократной загрузки одной страницы.

## Проверки и ограничения
- Изменения внесены в PR #4; требуется статическая повторная проверка текущего HEAD и реальный CI run.
- Node test не запускался локально: checkout и npm/node dependencies проекта недоступны в этой среде.
- Не выполнялись реальные Pinterest API вызовы, production DB изменения, deployment или merge.
