# AUD-185 — Идентификация Pinterest-профиля перед ручной сверкой

**Дата:** 2026-11-08  
**Область:** административная очередь Pinterest и ручное восстановление публикаций unknown  
**Статус:** исправление внесено в feature-ветку; production не затронут.

## Проблема

Карточка неизвестной публикации показывала внутренний UUID pinterest_account_id, но не показывала человеку, какой именно Pinterest-профиль связан с этой записью. При ручной сверке администратор мог видеть Pin ID и Board ID, но не имел наглядного подтверждения целевого Pinterest-пользователя. Это создавало риск сверить пин, найденный в другом профиле, и записать ложный статус published.

## Исправление

- Добавлена миграция 085_admin_pinterest_inventory_account_identity.sql.
- Ограниченный RPC инвентаря дополнен безопасными полями аккаунта: username, pinterest_user_id и признак connected.
- Аккаунт выбирается по точному совпадению pinterest_accounts.id и user_id с записью расписания. Токены, refresh tokens, scopes и другие credential-поля в JSON не попадают.
- В AdminPinterestSchedules добавлена карточка целевого Pinterest-профиля и его User ID; также виден признак подключения.
- Текст финального подтверждения теперь явно требует сверить пин именно в профиле, указанном в карточке.
- Backend mapper и unit test дополнены передачей только allowlisted метаданных профиля.

## Результат для пользователя

Оператор видит не только внутренний UUID, но и имя Pinterest-профиля и внешний Pinterest User ID. Перед ручным восстановлением проще обнаружить ситуацию, когда пин найден не в том аккаунте. Если профиль не определён, интерфейс явно показывает отсутствие имени/ID, а не подменяет их догадкой.

## Проверки и ограничения

- Статически проверено, что SQL возвращает только три allowlisted поля профиля и не включает токены.
- Добавлен unit test на передачу метаданных профиля через backend inventory.
- Полный frontend build, backend suite и PostgreSQL integration test не запускались в этой сессии.
- Миграция не применялась к Supabase/production; production не менялся, публикации и платежи не запускались.
